# Primeros Pasos con MATICERTS

Bienvenido a **MATICERTS**, la plataforma moderna para emisión y gestión de certificados digitales. Esta documentación te guiará paso a paso para integrar nuestra API REST en tu aplicación.

:::info ¿Qué es MATICERTS?
MATICERTS es una solución empresarial que permite emitir, validar y gestionar certificados digitales con seguridad OAuth 2.0. Perfecta para ERPs, CRMs, portales web y sistemas automatizados.
:::

---

## Elige tu Entorno

Contamos con dos entornos completamente independientes. Cada uno expone su propia **aplicación web** (el panel donde gestionas tu cuenta) y su propia **API REST** (la que integras en tu sistema).

<EnvironmentCards />

:::tip 🖥️ ¿Por dónde empiezo?
Entra primero a la **aplicación web** de Sandbox: ahí creas tu cuenta y generas el **Personal Access Token (PAT)** que necesitarás para llamar a la API. Cuando tu integración funcione, repite el proceso en Producción.
:::

### Parametriza la base URL

En los ejemplos de esta documentación usamos `{{URL}}` como marcador de la base URL de la API. Configúralo por entorno:

```bash title=".env"
# Sandbox
MATICERTS_API_URL=https://sandbox-api.maticerts.com

# Producción
# MATICERTS_API_URL=https://api.maticerts.com
```

:::warning 🔒 Buena Práctica de Seguridad
**Nunca hardcodees las URLs ni los tokens en el código.** Usa variables de entorno para cambiar entre Sandbox y Producción sin recompilar tu aplicación.
:::

## Autenticación: Elige tu Método

Todas las peticiones a MATICERTS deben incluir un **Bearer Token** en el encabezado `Authorization`. Ofrecemos dos métodos según tu caso de uso:

### Métodos Soportados

<Tabs groupId="auth-methods">
  <TabItem value="m2m" label="🤖 Backend (M2M) - Recomendado" default>

**Ideal para:** ERPs, CRMs, Cronjobs e integraciones automatizadas.

Usa un **Personal Access Token (PAT)** que generas desde el panel de administración
([Producción](https://app.maticerts.com/) · [Sandbox](https://sandbox-app.maticerts.com/)).

| | Ventaja |
| :--: | --- |
| ✅ | No expiran automáticamente |
| ✅ | Máximo rendimiento (sin ciclo de refresh) |
| ✅ | Revocables en cualquier momento desde el panel |

:::danger 🔑 Trata tu PAT como una contraseña
Guárdalo en variables de entorno, nunca en el repositorio ni en el código del navegador. Si se filtra, revócalo de inmediato desde el panel.
:::

  </TabItem>
  <TabItem value="frontend" label="👤 Aplicaciones Cliente">

**Ideal para:** Portales web, aplicaciones móviles e interfaces de usuario.

Obtén un token temporal autenticando al usuario final:


```bash
curl -X POST "{{URL}}/api/v1/auth/login" \
     -H "Content-Type: application/json" \
     -d '{
           "email": "usuario@empresa.com",
           "password": "tu-contraseña-segura"
         }'
```
  </TabItem>
</Tabs>

## Tu Primera Petición: Health Check

Verifica que tu conexión funciona correctamente. Reemplaza `<TU_ACCESS_TOKEN>` con tu token real:

<Tabs groupId="programming-languages">
  <TabItem value="curl" label="cURL" default>

```bash
curl -X GET "{{URL}}/api/v1/sistema/health" \
     -H "Authorization: Bearer <TU_ACCESS_TOKEN>" \
     -H "Accept: application/json"
```

  </TabItem>
  <TabItem value="javascript" label="Node.js / Fetch">

```javascript
const response = await fetch('{{URL}}/api/v1/sistema/health', {
  method: 'GET',
  headers: {
    'Authorization': 'Bearer <TU_ACCESS_TOKEN>',
    'Accept': 'application/json'
  }
});
const data = await response.json();
console.log(data);
```

  </TabItem>
  <TabItem value="python" label="Python (Requests)">

```python
import requests

url = "{{URL}}/api/v1/sistema/health"
headers = {
    "Authorization": "Bearer <TU_ACCESS_TOKEN>",
    "Accept": "application/json"
}

response = requests.get(url, headers=headers)
print(response.json())
```

  </TabItem>
</Tabs>
